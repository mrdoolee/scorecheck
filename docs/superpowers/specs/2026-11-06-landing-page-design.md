# 몇점(ScoreCheck) 랜딩 페이지 설계

작성 2026-11-06 · 앱 버전 0.8.0 기준

## 1. 목적과 이유

몇점은 교사가 나이스 성적 파일을 가져와 학생에게 PC 화면으로 성적을 보여 주고, 학생이 교사 휴대폰에 손으로 서명하면 원본 일람표 PDF 비고칸에 서명을 얹은 새 PDF를 만드는 Windows 앱이다. 다른 학교 교사에게 널리 배포하는 것이 목표다.

랜딩 페이지는 이 앱에 관심을 가진 **교사**가 앱이 무엇을 하는지 바로 이해하고 **설치 파일을 내려받게** 하는 한 페이지짜리 사이트다.

## 2. 목표 · 하지 않을 것 · 실패로 보는 것

목표

- 첫 화면에서 "**성적 확인은 PC로, 서명은 휴대폰으로**"가 한눈에 전달된다. 이것이 가장 중요한 메시지다(사용자 결정).
- 두 번째 메시지는 **PC 핫스팟 직접 연결 방식이 개인정보를 지킨다**는 점이다(사용자 결정).
- 어느 섹션에서든 다운로드 버튼에 쉽게 닿는다.

하지 않을 것

- 가격표, 고객 사례, 회원 가입, 로그인. 몇점은 무료이고 계정이 없다.
- 영어 페이지, 다크 모드 전용 디자인.
- 방문자 통계·추적 스크립트(앱의 "원격 측정 없음" 원칙과 어긋남 — 빌더 판단이 아니라 이 문서의 결정).

실패로 보는 것 (기술적으로 돌아가도 안 되는 것)

- **실제 학생 정보가 한 글자라도 페이지나 이미지에 들어가는 것.** `sample_data/`의 이름·점수·서명·PDF 조각은 어떤 목업에도 나오면 안 된다.
- 앱이 하지 않는 일을 한다고 쓰는 것(예: 아이폰 지원, 고등학교 양식 지원을 확인된 것처럼 쓰기).
- 석차·등수·백분위를 보여 주는 화면이나 문구. 앱은 이것을 만들지 않는다.
- 레퍼런스 사이트의 문구·그림을 가져오는 것.

## 3. 레퍼런스

https://illos-hourline-template.vercel.app/ — **섹션 흐름만** 빌린다. 문구·그림·브랜드는 가져오지 않는다(사용자 결정).

레퍼런스 흐름: 상단 메뉴 → 히어로(큰 한 줄 + 버튼 2개 + 제품 화면) → 대상별 기능 블록(글 + 숫자 강조 + 화면) → 3단계 설정 → 고객 사례 + 숫자 3개 → 단축키 → 가격표 → FAQ → 푸터. 장식보다 제품 화면이 주인공이고 문구가 짧고 구체적이다.

## 4. 섹션 구성 (사용자 확인)

1. **상단 메뉴** — 몇점 로고(앱 아이콘 `resources/icon.png`) · 사용 흐름 · 휴대폰 서명 · 개인정보 · 설치 · 자주 묻는 질문 · [다운로드] 버튼. 스크롤해도 위에 붙어 있음.
2. **히어로** — 제목 "성적 확인은 PC로, 서명은 휴대폰으로." 짧은 설명(나이스 파일을 넣으면 학생이 PC에서 본인 성적을 보고 선생님 휴대폰에 손으로 서명, 서명은 일람표 PDF 비고칸에). 버튼 [Windows용 무료 다운로드] [사용 흐름 보기]. 아래 작은 글씨 "무료 · 관리자 권한 없이 설치 · 앱은 인터넷에 접속하지 않음"(내 판단: 다른 PC에서 관리자 권한 없이 설치되는 것은 사용자 확인. 방화벽 허용 창까지 일반 계정에서 확인한 것은 아니라 "설치"로 좁힘). 오른쪽에 **PC 학생 화면 목업 + 폰 서명 화면 목업**을 겹쳐 배치(폰에 서명이 그려지는 움직임).
3. **세 단계 흐름** (레퍼런스의 3단계 설정 자리) — ① 나이스 파일 끌어다 놓기 ② 학생은 PC로 확인, 선생님 폰에 서명 ③ 비고칸에 서명이 든 PDF 저장. 단계마다 작은 목업.
4. **핵심 기능 블록 2개** (레퍼런스의 대상별 기능 블록 자리)
   - A. PC 성적 확인 — 평균과의 차이, 문항별 결과(문항별 전체 정답률), 짧은 피드백, 석차·등수 없음, 학생 화면 잠금.
   - B. 휴대폰 손서명 — QR 두 번이면 연결(핫스팟 접속 → 서명 페이지), 폰 화면 위쪽에 원본 일람표 본인 줄 표시, 서명은 원본 양식을 고치지 않고 비고칸 크기에 맞춰 얹음.
5. **핫스팟 연결 · 개인정보** (레퍼런스의 고객 사례 + 숫자 3개 자리) — 핵심 문장: **서명 데이터는 노트북과 서명용 휴대폰 사이에서만 오간다.** 그림: 노트북 ⇄ 노트북이 켠 핫스팟(WPA2) ⇄ 휴대폰, 학교망·인터넷·서버로는 나가지 않음. 숫자/짧은 강조 3개(예: 서버 0곳 / AES-256 암호화 / 앱은 인터넷에 접속하지 않음). 폰에 가는 것은 그대로 쓴다(내 판단, 최종 검토 후 PRIVACY.md 5절에 맞춤): 반·번호, 가운데를 가린 이름, 일람표 본인 줄 그림(머리글과 본인 행. 이 줄의 이름·점수가 보임)뿐, 다른 학생 정보는 가지 않음. 폰이 PC로 보내는 것은 서명 획 좌표뿐. 근거는 `PRIVACY.md` 4·5절.
6. **덤: 문항 분석** (레퍼런스의 단축키 같은 작은 부가 섹션) — 정답률 · 변별도 · 매력적인 오답 · 반별 비교, 학생 이름 없이 집계만 xlsx로. 교사 전용 화면.
7. **설치 · 준비물** (레퍼런스의 가격표 자리) — 무료. Windows 노트북·PC(무선랜이 있어 모바일 핫스팟을 켤 수 있어야 함), 안드로이드 휴대폰 + 크롬. 핫스팟 안내 문장(사용자 요청 방향): "노트북이 학교 Wi-Fi나 유선에 연결된 상태에서 핫스팟을 켭니다. 서명 데이터는 노트북과 휴대폰 사이에서만 오가고, 학교망이나 인터넷으로 나가지 않습니다." 무선랜이 없는 PC는 PC 화면 서명으로 대신할 수 있음. 처음 한 번 크롬 '근처 기기' 권한 허용 안내. SmartScreen 경고("추가 정보 → 실행"), 방화벽 허용 안내. [다운로드] 버튼.
8. **자주 묻는 질문** — 후보: 학교 업무망에서도 되나(사용자 확인: 학교 PC를 업무망에 연결한 상태로 핫스팟을 켜고 폰 서명까지 성공. 단 학교마다 정책이 달라 "모든 학교에서 된다"고는 쓰지 않음) / 학생 정보는 어디에 저장되고 언제 지워지나 / 핫스팟이 안 켜지면 / 폰이 연결 안 될 때(`ERR_TOO_MANY_RETRIES`, 근처 기기 권한) / SmartScreen 경고 / 처음 연결할 때 Windows 방화벽 창(허용 필요) / 아이폰은 되나 / 고등학교·다른 학년도 되나 / 석차는 왜 없나.
9. **푸터** — 제작 두리쌤. 이용 조건(앱 안 문구 그대로: 교육 목적 자유 사용, 재배포 시 출처 유지, 임의 수정본 재배포 금지, 수정 요청은 연락처로). Instagram `https://www.instagram.com/trdoolee`, 블로그 `https://blog.naver.com/trdoolee`. 개인정보 처리 안내(`PRIVACY.md`) 링크. 글꼴 라이선스 표기. GitHub 저장소 링크.

## 5. 사실 확인이 필요한 문구 (지켜야 할 제약)

- **아이폰: 아직 확인 안 됨**(사용자 확인). "아이폰 지원"이라고 쓰지 않는다. FAQ에서 "안드로이드 크롬에서 확인했고, 아이폰은 아직 확인 전"이라고 정직하게 쓴다. 준비물에도 안드로이드만 적는다.
- **지원 양식: 중학교 나이스 양식으로만 확인**(정기고사 교과목별 일람표, 수행평가 강의실별 일람표). 학교·학년·반 수·과목은 하드코딩하지 않았지만 고등학교 양식은 확인 전이라고 쓴다.
- 기능·개인정보 문구는 `README.md`, `PRIVACY.md`, `src/shared/guide.ts`, `src/shared/privacy.ts`의 현재 내용과 어긋나면 안 된다. 쓰기 전에 코드에서 확인한다.
- 학교 핫스팟·망분리 정책은 학교마다 다르다. "어느 학교에서나 된다"고 쓰지 않는다.

## 6. 만드는 방식

사용자 결정

- 페이지 HTML은 GitHub 저장소에 올리고 **Vercel**에 연결해 공개한다.
- 설치 파일은 **GitHub Releases**로 배포한다.
- 화면 그림은 **HTML·CSS로 앱 모양을 흉내 내 그린 목업**이고 살짝 움직인다(2026-11-07 변경: 가짜 데이터로 앱을 띄워 찍는 스크린숏은 작업이 무거워 취소).
- 분위기: **교무실 종이 느낌** — 미색 바탕(시안 기준 `#fbf8f1`), 남색 글씨(`#1d2b4f`), 핵심 단어에 노랑 형광펜 밑줄(`#ffe27a`), 다운로드 버튼은 남색 바탕 흰 글씨. 시안: `.superpowers/brainstorm/*/content/visual-style.html`의 C.

내 결정 (사용자가 바꿀 수 있음)

- 위치: 이 저장소의 `site/` 폴더. 빌드 도구 없는 정적 HTML·CSS(필요하면 소량의 JS). Vercel 프로젝트의 Root Directory를 `site`로 둔다.
- 다운로드 버튼은 `https://github.com/<계정>/<저장소>/releases/latest` 페이지로 보낸다. 설치 파일 이름에 버전이 들어가 있어(`ScoreCheck-Setup-0.8.0.exe`) 바로 받기 링크는 버전마다 바뀌기 때문이다. 저장소 주소는 아직 없으므로 **한 곳(상수 하나)**에 모아 두고 나중에 한 줄만 바꾸면 되게 한다. 그 전까지는 임시 값으로 둔다.
- 글꼴: 앱과 같은 학교안심 산뜻돋움 L·M(`resources/fonts/*.otf`, SIL OFL 1.1)을 페이지에 직접 넣는다. 외부 CDN·Google Fonts는 쓰지 않는다. 원본 OTF가 각 약 600KB라 웹용으로 줄이는 방법(woff2 변환, 글자 subset)은 빌더 판단. OFL 라이선스 전문을 `site/`에 함께 둔다.
- 외부 스크립트·폰트·이미지 요청 없음. 모든 자원은 `site/` 안에.
- 휴대폰 너비에서도 깨지지 않게 반응형으로 만든다(교사가 폰으로 링크를 열 가능성이 높음 — 내 추측).

### 앱 화면 목업

- 실제 앱 화면을 보고 모양(배치, 색, 카드, 버튼, 글꼴)을 흉내 낸 HTML·CSS 목업. 이미지 파일이 아니라 페이지 안의 HTML이라 선명하고 가볍다.
- 목업 속 앱 부분은 앱 색(하양 바탕, 보라파랑 `#635bff` 등 `src/renderer/src/styles.css`)을 써서 "앱 화면"으로 보이게 하고, 페이지 바탕은 종이 느낌을 유지한다.
- 목업 속 이름·점수·학교는 전부 지어낸 값(학교 `가온중학교`, 주인공 학생 2반 7번 `윤하늘`). 실제 `sample_data/`의 값과 겹치면 안 된다.
- 움직임은 살짝: 폰 화면에 서명이 그려지고 → PDF 비고칸에 서명이 나타나는 정도, 파일이 끌려 들어가는 정도. 반복은 느리게, `prefers-reduced-motion`이면 멈춘 그림.
- 필요한 목업: 히어로(PC 학생 화면 + 폰 서명), 세 단계(파일 넣기 / 학생 확인·서명 / 비고칸에 서명 든 PDF), 핫스팟 연결 그림, 문항 분석 작은 그래프.
- 실제 QR 코드는 그리지 않는다(모양만 흉내 낸 무늬).

## 7. 공개 저장소와 개인정보 검토 (사용자 결정: 필수)

앱 소스 저장소를 **그대로 공개**한다. 공개 전에 반드시 개인정보 검토를 한다.

- `git log --all` 전체 기록(지금 파일뿐 아니라 과거 커밋·삭제된 파일 포함)에서 실제 학생 이름·학번·점수·서명, 실제 학교 이름, 나이스 원본 파일 조각이 없는지 확인한다.
- 대상: 소스, 테스트(기대값에 실제 이름·점수가 박혀 있지 않은지), `설계_청사진.md`·`성적확인_서명_데스크톱앱_개발명세.md` 등 문서, `scripts/phase0/`(패킷 캡처·진단 출력), `.dorms-check/`, `docs/`, 이미지 파일.
- 발견되면 공개 전에 사용자와 처리 방법(파일 수정, 기록 정리 등)을 정한다. 기록을 다시 쓰는 작업은 사용자 승인 없이 하지 않는다.
- 검토 결과를 사용자에게 보고하고, 사용자가 확인한 뒤에 저장소를 공개한다.

## 8. 빌더에게 맡기는 것

- 섹션별 세부 문구(위 메시지와 사실 확인 제약 안에서). 짧고 구체적으로, 교사 말투로.
- 레이아웃 세부, 여백, 목업 배치와 세부 모양, 작은 움직임(과하지 않게).
- 이미지 형식·압축, 글꼴 경량화 방법.
- 핫스팟 연결 그림을 SVG로 그릴지 등 표현 방법.
- 페이지 제목·설명 메타태그, 공유 미리보기 이미지(og:image).
